# Классификатор 11v2

## Статус и границы

Актуальный локальный просмотр после второго разбора:
`reports/classification-v11v2/pilot-5/review.html`.

11v2 — отдельный движок на той же одобренной сетке 67 тем V11.
По разрешению владельца подключён к публикации, экспорту, API и основной карте.
Данные меняются только явными `publish --apply` и `export --apply`; пилотные
отчёты сами по себе карту не изменяют. Независимая точность пока не измерена.
Старый `classify_catalog.py publish` продолжает отвергать формат 11v2:
для новой версии используются команды `classify_catalog_v11v2.py`.

Используется локальный E5-small FP32, CPU, прежний SQLite-кеш векторов.
Новые нейросетевые веса не скачиваются; Telegram и внешние ML API не вызываются.
Сам E5 не дообучался: переработаны модель принятия решения, эталоны тем и
независимый лексический сигнал TF-IDF. Это ещё не обученный на владельческой
разметке линейный классификатор. В `config/classification_labels.json` сейчас
нет размеченного корпуса, а пяти известных ошибок для такого обучения и
оценки 67 классов недостаточно. Прежняя ручная разметка V9/V10 относится к
другой сетке: её можно подключать после проверки соответствия новых тем,
а не автоматически превращать старые широкие ответы в узкие. Текущие автоматические метки не используются
как достоверные обучающие ответы.

## Что изменилось

1. Профиль и каждый пост оцениваются отдельно, без сведения всех постов
   в один усреднённый смысловой вектор. Для темы используются несколько
   формулировок эталона; для проблемных областей добавлены предметные примеры.
2. Семантический сигнал E5 объединяется с независимым лексическим сходством
   TF-IDF по символьным n-граммам. Словарь строится на определениях и
   существующих тематических ключевых словах, не на предсказанных метках каналов.
3. Служебные сообщения, малосодержательные тексты и близкие повторы исключаются
   из входа модели. Причины видны в отчёте. Исходные кеши не переписываются.
4. Вес профиля адаптивный: базово 0,45; при явной предметной идентичности —
   0,70; при нехватке содержательных постов — не менее 0,75. Эти коэффициенты
   являются исследовательской политикой, а не калиброванными вероятностями.
5. Предметная идентичность не равна владельцу: название банка без банковского
   содержания не принуждает к теме банков. Если устойчивые посты явно
   противоречат прежнему описанию, повышенный приоритет профиля снимается.
6. Для пособий, родительства, кулинарии и садоводства нужны предметные
   свидетельства, а не упоминание ребёнка, продукта или предприятия в новости.
7. Узкая тема больше не обязательна. При неоднозначности результат содержит
   только раздел (`topic_granularity=group`) либо отказ (`abstain`).
   `suggested_topic` сохраняется для диагностики, но не выдаётся за назначение.
8. Ручные ответы имеют приоритет. Правил по username пяти примеров нет.

Оценки кандидатов теперь могут выходить за диапазон 0–1. Это ранжирующие
баллы гибридного алгоритма, **не доля уверенности и не вероятность**.

## Территориальная направленность

Направленность определяется отдельно от географии сюжетов и аудитории:

- название/описание должны выражать территориальную задачу канала;
- повторяемость страны в постах сама по себе не назначает эту страну;
- военная/международная аналитика о нескольких странах допускает `global`;
- предметный канал без территориального назначения может получить `nonlocal`;
- при нехватке оснований сохраняется `unknown`, а не придуманная страна;
- Россия детализируется до региона, зарубежные места — до страны;
- Москва не объединяется с Московской областью; Владивосток — Приморский край.

Для новых предложений сохраняются список упоминаемых мест, свидетельства
и обязательный статус проверки. Не выводятся страна автора, политическая
принадлежность и география подписчиков. Исправлены известные лексические
ложные срабатывания: «для того / из того» → Того, «самой» → Самоа,
«Владимир Путин» → Владимирская область. Старый геоклассификатор V11 не изменён.

## Запуск

Команды из корня проекта, в прежнем Python-окружении. Каждому расчёту нужна
новая папка; существующие эксперименты не заменяются.

```powershell
# Только локальные данные; пилот 120 каналов, включая известные примеры владельца.
python -u scripts/classify_catalog_v11v2.py classify --limit 120 --include-development --output reports/classification-v11v2/pilot-next-1

# Весь текущий каталог, без нового сбора и без изменения основной карты.
python -u scripts/classify_catalog_v11v2.py classify --output reports/classification-v11v2/catalog-1

# Повторный расчёт строго сохранённых входов.
python -u scripts/classify_catalog_v11v2.py classify --input reports/classification-v11v2/pilot-5/snapshot.json --frozen-evidence reports/classification-v11v2/pilot-5/evidence.json --output reports/classification-v11v2/repeat-1

# Отдельная проверка примеров разработки.
python scripts/classify_catalog_v11v2.py evaluate --run reports/classification-v11v2/pilot-5 --labels config/classification_v11v2_development.json
```

В папке результата: `snapshot.json`, `evidence.json`, `policy.json`,
`results.json` и автономный `review.html`. В результатах указаны хеши входов,
политики, реализации и словаря. Полные тексты остаются в локальном отчёте.
Срок пригодности постов сохраняется; замороженный устаревший кеш не объявляется
свежим. Лимит обработки по умолчанию — 3600 секунд, `--seconds` — до 28800.
При `remaining > 0` результат частичный, код завершения 2; новый запуск получает
новую папку, но использует уже рассчитанные векторы.

В просмотре есть сравнение V11/11v2, отдельное объяснение весов профиля,
кандидатов профиля и отдельных постов, исключённых сообщений, географии,
экспорт/импорт ручных оценок. Формат и хранилище оценок 11v2 отделены от V10/V11.
Оценки темы и географии независимы: можно согласиться с темой, но отметить
ошибку направленности, выбрать её тип и записать правильную страну/регион.
Оценки автоматически не обучают модель и не меняют рабочую карту.

### От новой классификации до основной t-SNE-карты

Все команды выполняются из корня проекта в прежнем Python-окружении.
Папки должны быть новыми: при повторном расчёте используйте `catalog-2`
и `tsne-2`. Новый сбор Telegram не нужен: читается готовый локальный кеш.

```powershell
$run = "reports/classification-v11v2/catalog-1"
$layout = "reports/classification-v11v2/map-layout/tsne-1"

# 1. Классифицировать весь текущий каталог. Не указывайте --limit.
python -u scripts/classify_catalog_v11v2.py classify --output $run

# 2. Открыть $run/review.html. В results.json должно быть remaining: 0.
# Проверка публикации без записи: проверяется также полный состав каталога.
python -B scripts/classify_catalog_v11v2.py publish --run $run

# 3. Применить проверенный результат и экспортировать текущие JSON/JS.
python -B scripts/classify_catalog_v11v2.py publish --run $run --apply
python -B scripts/classify_catalog_v11v2.py export --apply

# 4. Пересчитать t-SNE уже по обновлённым темам и регионам.
python -B scripts/build_atlas_layout.py compare --methods tsne --output $layout

# 5. Просмотреть $layout/comparison.html и применить готовые координаты.
python -B scripts/build_atlas_layout.py publish --input "$layout/tsne.json" --apply
```

Не переходите к следующему шагу при ошибке предыдущей команды. При частичной
классификации используйте новый расчёт с большим `--seconds` (до 28800),
а не публикуйте неполный результат как полный. Существующие векторы кешируются.

Результат публикации хранится отдельно в
`reports/classification-v11v2/catalog.json`. Прежняя V11 остаётся в своём
каталоге; её файлы не заменяются. Старые публикации 11v2 архивируются рядом
под именем `catalog-previous-<время>.json`. Предыдущие рабочие
`channels.json` и `channels.js` независимо сохраняются в
`reports/classification-v11v2/export-backups/<время>/`.

Без `--apply` команда `export` создаёт отдельный предварительный JSON
(можно указать новое имя через `--output`). Обновление t-SNE отдельно
архивирует прежние координаты штатным механизмом раскладки.

По умолчанию нельзя опубликовать 120-канальный пилот вместо 3000 каналов,
даже если у пилота `remaining: 0`. Публикация проверяет состав текущего
каталога, исходный снимок, свежесть, политику, профили, темы и географию
до первой записи. `--allow-partial` существует только как явное разрешение
оператора; для обычного обновления карты его использовать не нужно.

Если профиль изменился после расчёта, предложение не подставляется к другому
профилю. Ручные темы и география сохраняют приоритет. API и экспорт читают
готовый кеш без импорта ML-пакетов и запуска модели.

В публичном формате раздел сохраняется как `subcategory=other` с реальным
`topic_group` и `topic_granularity=group`; отказ — как `other/other_group`
с `topic_granularity=abstain`. При этом старые тематические теги сбрасываются:
например, CFO не остаётся в фильтре «Личные финансы». Интерфейс явно показывает
«без уточнения подтемы» или «Тема не определена». Кандидат не становится темой.

После экспорта и до применения новых координат старая t-SNE-проекция может
стать несовместимой: карта временно покажет схему. Новые координаты учитывают
очищенные профиль/посты 11v2, локальные клиники и региональные каналы с
определённым только новостным разделом. Режим группировки по регионам остаётся
схематичным. Фильтры не пересчитывают координаты.

Проверка интеграции на изолированных данных:
`node tests/classification-v11v2-map.cjs`. Она не заменяет рабочие файлы.

## Следующий рубеж перед включением в основу

Разметить новые случаи по темам и направленности отдельно, включая
контрпримеры: банковский канал о путешествиях, городские новости о детях,
военная аналитика с частыми упоминаниями одной страны, настоящий родительский
или кулинарный канал, предметный канал с городом в биографии. Часть новой
разметки зафиксировать как holdout до следующего изменения настроек.

Формат меток: `atlas-classification-evaluation-v1`, `split=holdout`, список
`cases` как в development-файле. Все известные development-username запрещены в holdout.
Отдельно измерять темы, разделы, охват узких назначений/отказов и географию.
Для обучения лёгкого линейного классификатора затем использовать только
учебную часть проверенной разметки, не holdout и не текущие автоматические ответы.

## Второй разбор: финансовые каналы и локальная медицина

`pilot-5` использует побайтно те же 120 профилей и кеш постов, что `pilot-3`.
Добавлены три новых development-примера владельца; они не стали holdout.
Текущие данные, карта и старые отчёты не заменялись.

### Иерархический выбор раздела

Теперь 18 разделов имеют собственные смысловые эталоны и лексическое
сопоставление, а не оцениваются только через максимальный балл подтемы.
Итог раздела объединяет прямой сигнал и две лучшие подходящие подтемы.
Если раздел подтверждается согласованными сигналами, близость двух подтем
не превращается в полный отказ. Старые пороги не уменьшались глобально.
Для пустого профиля один случайный перевес прямого раздела недостаточен.

Расширены эталоны макроэкономики, управления финансами компании и учёта.
Дисклеймер «не инвестиционные рекомендации» исключён из тематического входа.
Учитывается профессиональная идентичность CFO с подтверждением постами:
корпоративный бюджет не считается личным, а инструменты финансового директора
не превращают весь канал в инвестиционные советы. Название должности без
подтверждения постами не принуждает к профессиональному разделу.

| Канал | Новое предложение |
| --- | --- |
| Дмитрий Голубовский | Макроэкономика и рынки |
| Финансовый директор / Мастер CFO | Бизнес, работа и продвижение — только раздел; кандидаты управление и учёт |
| ГИНЕКОЛОГИЯ РЖД БАТАЙСК | Медицина и здоровье; Ростовская область |

Корпоративные финансы не выделены автоматически в новую подтему: текущая
сетка содержит управление и бухгалтерский/управленческий учёт, но не отдельную
подтему CFO. Широкий деловой раздел здесь намерен, а не означает отсутствие
содержания. Новая узкая ниша требует согласования владельца.

### Справочник и назначение локальных услуг

В `config/geography_v11v2.json` добавлено отдельное дополнение для 11v2:
Батайск → Ростовская область, с точными формами названия. Старые справочники
V11 не меняются. Покрытие городов остаётся неполным; это не полный ФИАС.
Глагольные формы «читаю/читает/читают» исключены из распознавания Читы;
настоящая Чита по-прежнему относится к Забайкальскому краю.

Локальные клиники/отделения могут выражать территориальную задачу не словами
«новости города», а названием учреждения с городом, приёмом и адресом.
Такие свидетельства учитываются отдельно. Город из биографии врача сам
по себе не задаёт регион. Для Батайска правильный регион подтверждён названием
и повторяющимися адресами; ложный кандидат из слова «читаю» исчез.
