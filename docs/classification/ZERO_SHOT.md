# Локальная zero-shot проверка 100 каналов

Скрипт `scripts/benchmark_zero_shot.py` сравнивает текущую классификацию с NLI-моделью `MoritzLaurer/mDeBERTa-v3-base-mnli-xnli`. Telegram не запрашивается. База, ручные ответы и файлы карты не изменяются. Работа с PostgreSQL выполняется в read-only транзакции.

## Установка

Из корня проекта, в отдельном окружении PowerShell:

```powershell
python -m venv .venv-zero-shot
.\.venv-zero-shot\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m pip install -r requirements-zero-shot.txt
```

`requirements-zero-shot.txt` содержит диапазоны версий необязательных зависимостей, не проверенный lock. Для повторения эксперимента сохраните версии своего окружения (`python -m pip freeze`). Первый запуск скачивает веса и токенизатор с Hugging Face. После загрузки вычисления локальные; тексты каналов не отправляются в API. Модель хранится в обычном кеше Hugging Face. Понадобятся место на диске и оперативная память; время на CPU зависит от компьютера. По умолчанию GPU не требуется.

## Запуск

Сразу по рабочей базе из `.env` (в вашем случае `PG_DATABASE=tg_parser_atlas`):

```powershell
python -B scripts/benchmark_zero_shot.py --database --limit 100 --output reports/zero-shot-100
```

Либо по существующей выгрузке JSON — удобно для одного неизменного снимка:

```powershell
python -B scripts/benchmark_zero_shot.py --input reports/audit-3000/channels-baseline.json --limit 100 --output reports/zero-shot-snapshot-100
```

Необязательно сначала делать новый экспорт. Если используется экспорт по умолчанию, команда без `--database` читает `web/data/channels.json`.

В выборку попадают каналы с содержательным описанием. Она детерминирована (`--seed 42`): каналы берутся по очереди из разных текущих тематик, внутри каждой порядок случайный. Это тематически сбалансированная диагностическая выборка, не случайная оценка точности всего каталога. Если подходящих записей меньше 100, обрабатывается доступное количество, которое выводится в консоли.

Вход модели — название и очищенное от служебных контактов описание. Username и исходная тема не передаются модели. По умолчанию текст ограничен 2000 символами, затем токенизатор может дополнительно обрезать его до лимита модели. Точный поданный текст сохраняется в отчёте.

Используются все актуальные темы, кроме `other`: NLI всегда ранжирует предложенные предметы, а надёжного автоматического отказа пока нет. Для близких отраслей заданы развёрнутые определения. Остальные описания берутся из таксономии. Все определения и версия таксономии записываются в JSON. Форматы, география и дополнительные теги этим экспериментом не определяются.

## Результат и продолжение

Файлы сохраняются **на вашем компьютере**, относительно корня проекта:

- `reports/zero-shot-100.csv` — Excel/LibreOffice: UTF-8 с BOM, разделитель `;`.
- `reports/zero-shot-100.json` — параметры, выборка, определения классов, ревизия модели и первые пять кандидатов каждого канала.
- `reports/zero-shot-100.summary.json` — распределение прогнозов и число расхождений с действующими правилами.

В CSV есть текущая тема и её источник, первый и второй прогнозы модели, оценки, разрыв и признак расхождения. Для ручной проверки оставлены `expected_topic` и `reviewed`. Это отдельный сравнительный формат: он не предназначен для `classification_quality.py apply/evaluate`. Для подтверждённой разметки проекта используйте стандартную HTML-форму.

После каждого канала сохраняются все три файла. Чтобы продолжить после Ctrl+C или ошибки, повторите ту же команду с `--resume`:

```powershell
python -B scripts/benchmark_zero_shot.py --database --limit 100 --output reports/zero-shot-100 --resume
```

Изменение исходных профилей, текущих назначений, выборки, определений или параметров требует нового `--output`. Завершённый отчёт повторно не вычисляется. Не запускайте два процесса с одинаковым `--output`.

Опции:

- `--device cuda:0` — использовать доступный GPU с подходящей установкой PyTorch;
- `--batch-size 4` — размер внутренних NLI-пакетов, уменьшите до 1 при нехватке памяти;
- `--max-chars 2000`, `--seed 42` — длина текста и выборка;
- `--model ...`, `--revision COMMIT` — другая NLI-модель или фиксированная ревизия;
- `--labels labels.json` — JSON-словарь `ID → определение` для всех текущих тем, кроме `other`.

Оценки NLI не являются калиброванной вероятностью правильности. Расхождение с действующими правилами — повод для проверки, не доказанная ошибка. Проверяйте также совпадения. Не подбирайте определения классов по итоговому контрольному набору. Тесты скрипта подменяют инференс и проверяют выборку, отчёты, продолжение и read-only режим; качество реальной модели оценивается вашим запуском.
