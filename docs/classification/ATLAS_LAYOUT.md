# Раскладка «АТЛАС»

## Что показывает карта

В продуктовом интерфейсе «Темы» не показывает географические подписи/подгруппы,
«География» отдельно отбирает подходящие каналы с указанной территорией.
Подробности и ограничения: [FRONTEND.md](../../FRONTEND.md). Старые опубликованные
t-SNE-координаты сохраняются: это не новый пересчёт расстояний без географии.

Быстрая схема группирует каналы по теме и условному локальному контексту.
Она не вычисляет сходство текстов. Упаковка островов масштабируется вместе
с их радиусами: ограниченной спирали с запасным размещением справа больше нет.
Постоянные контуры убраны; «Подсветка» включает только мягкие пятна плотности.

Местные новости, ЧП, ЖКХ и афиша получают региональные подгруппы.
Недвижимость, вакансии и другие пограничные темы — при признаках локального
содержания в профиле. Предметные каналы, включая крипту и бизнес, не делятся
по одному лишь записанному региону. Явное локальное сообщество — исключение.
Предварительные региональные метки влияют слабее подтверждённых.
Неизвестная география не создаёт отдельный огромный остров.
За пределами России используется страна; географические фильтры сохраняются.
Эта политика не изменяет классификационные поля каналов.

## Настоящие UMAP и t-SNE

```powershell
python -B scripts/build_atlas_layout.py compare --output reports/classification-v11/map-layout/comparison-1
```

Каждому запуску нужна новая папка. Команда **не обращается к Telegram**,
не возобновляет сборщик, не меняет каталог и не публикует координаты.
Использует только локальные веса E5-small и кеш постов. При отсутствии весов
завершается ошибкой, а не скачивает модель. Дополнительные зависимости:
`requirements-layout.txt`.

В папке сохраняются замороженные `snapshot.json`, `evidence.json`,
`comparison.json`, автономный `comparison.html`, а также успешные
`umap.json` / `tsne.json`. Посты и профили в этих файлах предназначены для
локального исследования, не для автоматической публикации в репозиторий.
Нельзя сравнивать методы, запущенные на разных изменяющихся снимках.

Для повторного расчёта ровно того же снимка, без чтения обновлённого кеша:

```powershell
python -B scripts/build_atlas_layout.py compare --input reports/classification-v11/map-layout/comparison-1/snapshot.json --frozen-evidence reports/classification-v11/map-layout/comparison-1/evidence.json --output reports/classification-v11/map-layout/comparison-2
```

Для канала с минимум тремя подходящими постами используется смесь
25% профиля и 75% среднего вектора постов (до восьми). Иначе — только профиль.
Оба метода получают одинаковые векторы и одинаковые симметричные расстояния
с мягким региональным контекстом. Принадлежность к теме не подмешивается
в текст вектора. После проекции устраняются пересечения точек; метрики
считаются уже по итоговым координатам.

Сохранение соседей, соседство одинаковых текущих тем/регионов и пропорции
карты — диагностика визуализации, **не точность классификатора**.
Предварительные метки не являются независимым эталоном. Далёкие острова
не имеют буквального общего масштаба смыслового расстояния.

## Явная публикация выбранного метода

Сначала проверка без записи:

```powershell
python -B scripts/build_atlas_layout.py publish --input reports/classification-v11/map-layout/comparison-1/umap.json
```

Только после просмотра, выбора и разрешения на публикацию добавляется `--apply`.
Публикуются `web/data/atlas_layout.json` и `web/data/atlas_layout.js`;
прежние версии независимо сохраняются в
`reports/classification-v11/map-layout/backups/`. Каталог каналов не меняется.

Артефакт должен содержать полный набор узлов текущего каталога, совпадающие
входы и политику, корректную конечную геометрию и возраст не более семи дней.
Браузер не запускает модели: читает координаты и при несовместимости возвращается
к схеме. Локальная правка темы также отключает семантический снимок.
Режим регионов остаётся схематичным. Обычные фильтры меняют видимость,
а не расположение точек.

Общая политика: `config/map_layout.json`. После изменения:
`python -B scripts/sync_layout_policy.py`.

## Первое локальное сравнение

Результат: `reports/classification-v11/map-layout/comparison-2/comparison.html`.
Повторный расчёт использовал побайтно те же `snapshot.json` и `evidence.json`,
что первый запуск. Первый результат не заменён: он зафиксировал отказ
проверки пересечений; после исправления остаточные наложения устраняются
локальным поиском свободной позиции, без глобального горизонтального хвоста.

Снимок: 3000 каналов, 1485 с постами, 1515 только с профилем. Из 305 регионально
значимых каналов все имеют предварительные геометки: независимой проверки
регионального соседства на подтверждённых метках здесь нет.

| Диагностика итоговых координат | UMAP | t-SNE |
| --- | ---: | ---: |
| Сохранение исходных смысловых соседей (15 ближайших) | 17,1% | 22,7% |
| Сохранение соседей с региональными ограничениями | 17,3% | 23,1% |
| Доля соседей с той же текущей темой | 24,2% | 26,2% |
| Ширина / высота | 1,06 | 0,59 |
| Проекция, раздвижение точек и диагностика | 33,7 с | 18,0 с |
| Пик памяти процесса | 922,7 МБ | 924,9 МБ |

Время в таблице не включает подготовку векторов. Минимальное расстояние
между центрами после округления — около 24 единиц для обоих методов;
радиусы точек не превышают 7. t-SNE — более перспективный кандидат для просмотра
на этом снимке, но сохранение соседства невысокое, и победитель не опубликован.
Схема остаётся основной: после актуального браузерного обогащения её пропорции
по темам — 1,02 вместо прежних 3,92. Полный Python-набор: 292 теста,
38 пропусков; браузерные сценарии и сравнение обоих артефактов прошли.

## Уточнение t-SNE и визуального слоя

По выбору владельца доработан t-SNE; новый автономный просмотр:
`reports/classification-v11/map-layout/tsne-refined-1/comparison.html`.
Снимок и посты побайтно совпадают с `comparison-2`; классификационные поля
не переписывались. Основная карта автоматически на этот артефакт не переключалась.

Визуальный слой: тёмное поле без координатной сетки, более мелкие точки,
нейтральные двухстрочные подписи без счётчиков. На общем плане показываются
разделы; при приближении появляются темы и регионы, а затем подписи групп
плавно исчезают. Масштаб переходов отсчитывается от обзора всей карты, а не
от фиксированного размера экрана. Подписи не сдвигаются к одной верхней линии
и проверяются на наложение в экранных координатах. Скрытые фильтром каналы
не оставляют подписи. Регион подписывается у локальной концентрации минимум
двух каналов, а не у среднего центра произвольно разбросанных точек.

В политике версии 2 профильное свидетельство должно относиться именно
к выбранному региону. Раньше совпадение для другого кандидата могло ошибочно
включить региональную роль пограничной темы. Предварительная геометка
с собственным профильным свидетельством получает вес 0,9, без него — 0,5;
это **сила влияния в раскладке, не вероятность и не подтверждение владельца**.
Притяжение одинаковых регионов усилено только для локально значимых каналов.
Крипта, бизнес и другие предметные темы не превращены в региональные острова.

Диагностика до / после:

- Доля совпадения региона с ближайшим региональным соседом: **72,7% → 94,5%**.
  Одиночные регионы исключены: соответственно 293 и 291 оцениваемый канал.
- Прежняя метрика по региональным соседям среди 15 общих ближайших:
  **60,2% → 76,3%**.
- Сохранение исходных смысловых соседей: **22,7% → 21,4%**.
  Это наблюдаемый компромисс за более связные региональные группы.
- Региональных каналов: 305 → 303; память повторного процесса — 687 МБ.

Оставшиеся 16 случаев с чужим ближайшим региональным соседом находятся
в `tsne-regions.json`. Это геометрические выбросы для просмотра, а не
доказанные ошибки географии; метки из соседства автоматически не исправляются.
В просмотре добавлен фильтр локальных каналов и конкретного региона;
клик и наведение показывают геометку и её предварительный статус.
Проверены подписи на разных масштабах, фильтры без перемещения координат,
отсутствие JS-ошибок и подключение артефакта в основное приложение без записи
публичных файлов. Python-набор: 293 теста, 38 пропусков.

## Перенос выбранного результата в основную карту

По одобрению владельца `tsne-refined-1/tsne.json` применён командой
`publish --apply`. Основной режим «По темам» теперь читает именно эту
t-SNE-проекцию из `web/data/atlas_layout.json` (HTTP) или
`web/data/atlas_layout.js` (`file://`). Это не новый пересчёт: координаты всех
3000 каналов и подписи совпадают с одобренным просмотром. Новые собранные
посты автоматически не подмешивались; каталог и коллекция не менялись.
Прежних файлов `atlas_layout.*` при первом применении не было.

Режим регионов сохраняет отдельную схему; возврат к темам восстанавливает
те же t-SNE-координаты. Поиск и фильтры меняют видимость, не расположение точек.
При изменении каталога, локальной правке темы или устаревании снимка сохраняется
защитный переход к схеме — это не автоматическое переобучение карты.
После очередной публикации классификации координаты нужно пересобрать и
явно применить совместимый артефакт.

Проверка реально опубликованных файлов: `npm run test:published-layout`.
Она запускает основное приложение по HTTP и `file://`, проверяет точные
координаты, подписи, поиск, переключение группировки и мобильный экран.
## Если вместо t-SNE появилась схематичная раскладка

Под заголовком карты теперь показывается конкретная причина отклонения снимка,
а не только «требует обновления». Полная причина также доступна при наведении
на эту строку. Обновите страницу через Ctrl+F5, чтобы загрузить новую диагностику.

- Локальные ручные темы в продуктовом интерфейсе накладываются поверх совместимого
  t-SNE без перемещения точек. Снимок проверяется по исходным данным, а ручной ответ
  сохраняется в цвете, карточке и фильтрах. Строгий валидатор для других инструментов
  по-прежнему может сообщить «В этом браузере сохранена ручная тема @…».
- «Тема/география @… отличается…» — браузерная классификация и снимок различаются.
  Сначала проверьте обновление страницы и актуальность JS, а не пересчитывайте ML.
- Разное количество каналов или изменённые данные — проверьте соответствие
  channels.json и опубликованного atlas_layout.json.
- Дата в будущем — проверьте часы; срок более 7 дней — снимок устарел.
- Группировка по регионам намеренно использует отдельную схематичную раскладку.

Ручные ответы не удаляются автоматически. Несовместимости состава каналов,
геометрии, политики или версии исходных данных не обходятся. Диагностика теперь
находится в справке → «О данных и раскладке», не в постоянной плашке над картой.
