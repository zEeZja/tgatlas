# Основная V11: запуск владельцем

Переработка **11v2** имеет отдельные команды классификации, публикации и экспорта:
[CLASSIFICATION_11V2.md](CLASSIFICATION_11V2.md). Ниже сохранены команды прежней V11;
отчёты 11v2 ими публиковать нельзя.

Новый массовый сбор разработчиком **не запускался**, результаты на рабочую
карту не публиковались. Исходные данные и ручные ответы сохранены. Команды
ниже выполняются из корня проекта в его Python-окружении.

## Запуск по шагам

```powershell
# 1. Только существующие посты из read-only БД и свежих локальных снимков.
# Никаких обращений к Telegram. Фиксируется снимок каталога для этого запуска.
python -u scripts/classify_catalog.py collect

# 2. Получить недостающее из публичного превью Telegram.
python -u scripts/classify_catalog.py collect --http

# Состояние можно посмотреть из другой консоли:
python scripts/classify_catalog.py status

# 3. CPU-классификация: новая сетка + география. Без Telegram и внешних ML API.
python -u scripts/classify_catalog.py classify --output reports/classification-v11/result-1.json

# 4. Автономный HTML для просмотра перед публикацией.
python scripts/classify_catalog.py view --results reports/classification-v11/result-1.json --output reports/classification-v11/result-1.html
```

После просмотра откройте `reports/classification-v11/result-1.html` двойным
щелчком. Видны текущая/предложенная тема, посты, география и её кандидаты.
Оценки можно скачать в JSON; они не применяются автоматически.

Для включения результатов на основной карте и в API:

```powershell
python scripts/classify_catalog.py publish --results reports/classification-v11/result-1.json --apply
python scripts/classify_catalog.py export --apply
```

`publish` без `--apply` только проверяет файл. `export` без `--apply` создаёт
предварительный JSON в `reports/classification-v11/map-preview.json` (нужно новое
имя при повторном просмотре). `export --apply` заменяет рабочие
`web/data/channels.json` и `web/data/channels.js`, предварительно сохранив обе
прежние версии отдельно в `reports/classification-v11/export-backups/`.
Берётся текущий JSON, а не список из БД: ни новые каналы за время сбора, ни
каналы, отсутствующие в БД, из карты не удаляются. Устаревшие по профилю
предложения пропускаются. В этой разработке экспорт не запускался. После экспорта обновите
страницу карты; запущенному API может потребоваться перезапуск после изменения
конфигурации/кода. API по-прежнему работает со своим каталогом БД, применяя к
совпадающим профилям опубликованный кеш. Модели в экспорте, API и браузере не запускаются.
В публичной выгрузке сохраняются только короткие примеры публикаций, а не весь
корпус постов. Полные доступные материалы остаются в локальном запуске и отчёте.
Счётчик учтённых постов в карточке не подменяется числом показанных примеров.

## Лимиты и продолжение

По умолчанию: **восемь постов, одна страница на канал**, до 3000 каналов,
3000 запросов суммарно, один запрос не чаще чем раз в шесть секунд,
восьмичасовой срок запуска. Новые запросы после срока не ставятся;
уже начатый запрос ограничен timeout 20 секунд. Ориентир для 2000 недостающих
страниц — около 3,5–5 часов, не обещание фактического времени.

Telegram обычно возвращает 13–20 сообщений на странице. Мы сохраняем до восьми
подходящих текстов, но это не уменьшает размер HTML-ответа. Экономия HTTP по
сравнению с пилотом достигается одной страницей вместо двух. Медиа не скачиваются.
Вторая страница, автоматические повторы и перенаправления запрещены.

До HTTP используются локальные данные. Тексты должны быть не старше 30 дней,
содержательными, не дублироваться и не быть явно рекламными. Сам снимок —
не старше семи дней. Нужны минимум три пригодных публикации; узкий временной
охват не скрывается. Если материалов меньше, канал получает отметку о нехватке
постов, а не ложное подтверждение результата.

Все файлы запуска находятся в `reports/classification-v11/catalog-run/`:
`snapshot.json`, `collection.json`, `posts/`. Счётчик запросов сохраняется
**до отправки**, общий бюджет не сбрасывается при повторном запуске. Один и тот
же `--run` нельзя использовать двумя сборщиками одновременно. Блокировка
освобождается ОС при завершении процесса; вручную удалять lock-файл не требуется.

После обычного прерывания `Ctrl+C` повторите ту же команду `collect --http`:
используются готовые снимки, уже запрошенные каналы не запрашиваются второй раз.
Часть прерванного запроса может остаться недоступной — бюджет важнее скрытого
повтора. При HTTP 403/429 весь сбор останавливается; повтор той же команды
не снимает остановку. Не создавайте новые запуски для обхода ограничений Telegram.
Остаток каталога можно классифицировать по имеющимся данным, явно видя нехватку
постов. При исчерпании восьми часов автоматическое продление также запрещено.

Если остановка вызвана именно истечением времени, оператор может явно дать
новое окно (до восьми часов от момента команды):

```powershell
python -u scripts/classify_catalog.py collect --http --extend-hours 8
```

Сохраняются снимок, готовые посты, общий бюджет и счётчик запросов; продление
записывается в журнал. Этот флаг не снимает HTTP 403/429 и не увеличивает
исчерпанный бюджет запросов. Для нестандартного запуска укажите прежний
`--run` и те же `--posts`/`--requests`, с которыми он был начат.

В первый запуск можно выбрать меньше постов:
`collect --posts 5`, затем обязательно `collect --http --posts 5`.
Лимит — 3–8, увеличить его сверх восьми нельзя. Для отдельного эксперимента
задавайте новый `--run reports/classification-v11/another-run` во всех командах.
Снимок и лимиты уже начатого запуска менять нельзя. Каждый новый запуск
означает отдельное решение оператора о бюджете, а не автоматический retry.

### Windows: отказ в доступе при сохранении прогресса

Ошибка `WinError 5` при замене `collection.json.<случайное имя>.tmp` на
`collection.json` означает отказ ОС в атомарной замене, а не ответ Telegram.
Возможна кратковременная блокировка сторонним читателем/сканером; по одному
сообщению её причину установить нельзя. Замена повторяется ограниченно
(до восьми попыток, суммарная пауза 3,55 секунды) только для Windows-кодов
5/32/33. Старый файл не удаляется и не обнуляется. При постоянном запрете
ошибка остаётся видимой; права доступа и защитное ПО автоматически не меняются.

После завершения упавшего процесса проверьте `python scripts/classify_catalog.py status`
и повторите прежнюю команду `collect --http`. Не удаляйте `collection.json`,
`snapshot.json`, папки постов и счётчики. Уже учтённые запросы не повторяются.
Если к моменту продолжения истёк срок, используйте явное продление выше.

Классификация ограничивает постановку блоков, а не мгновенно прерывает текущий
forward. По умолчанию лимит — 3600 секунд; `--seconds` допускает до 28800.
В результате есть `remaining`. Частичный результат не публикуется без явного
`--allow-partial`. Для повторных результатов используйте `result-2.json` и т. д.,
существующие отчёты не заменяются.

## Что внедрено в основу

`config/classification_v11.json` включает новый основной контур. Одобренная
сетка: 18 разделов и 67 подтем, включая найденную по пилоту «Афишу и досуг».
Идентификаторы новой сетки имеют префикс `v11_`, поэтому не конфликтуют со
старыми головами, метками и кешами. Исторический файл черновика оставлен
неактивным архивным источником; одобрение записано в основной политике.

После явной публикации экспорт/API читают V11 последним, браузер показывает
новые темы и географию, меню содержит новую сетку. Старые классы остаются для
совместимости и сохранения неоднозначных ручных ответов. Тема и география
имеют **независимый ручной приоритет**. Однозначные совместимые старые ручные
темы переводятся в укрупнённые новые с сохранением исходного ответа в
`legacy_classification`; широкие «Бизнес», «Госорганы», «Дизайн и мода» и другие
не преобразуются в узкие классы автоматически. Старые модели и CSV не меняются.

Точность новой сетки пока не проверена независимой разметкой. В основной карте
автоматические метки показываются **как предложения**, с соответствующим
источником, предупреждением и `topic_review_required=true`. Они используются
для экспериментальной навигации, но не выдаются за ручные/сертифицированные
назначения. При недостатке постов это отдельно отмечено. Ручные ответы не
заменяются моделью. Прототипы новой сетки не подменяются линейной головой V10,
поскольку смысл и набор классов изменились.

Ручные ответы именно новой версии можно записать отдельно в
`config/classification_v11_overrides.json`, например:

```json
{"format":"atlas-manual-classification-v11","channels":{
  "channel_username":{
    "topic":"v11_events_leisure",
    "geography":{"scope":"region","country":"RU","regions":["Приморский край"]}
  }
}}
```

Затем повторить классификацию в новый файл и публикацию. Не переносите сюда
предложения модели под видом ручных подтверждений. Тема или география могут
быть заданы по отдельности. Новые ручные ответы имеют приоритет над прежними.

## География: возможности и ограничения

* За пределами России — страна/территория, без зарубежных регионов.
* В России — регион проектного справочника; город помогает выбрать регион.
* Владивосток → Приморский край; Москва не равна Московской области.
* Не измеряется местонахождение подписчиков. Определяется направленность
  содержания, причём упоминание места не считается направленностью автоматически.

Обработчик сначала связывает названия и варианты написания со справочником,
затем учитывает роль профиля, повторение в разных постах, конкурирующие места,
семантическое сходство с локальной/международной/нетерриториальной направленностью.
Embeddings E5-small используются совместно с тематическим конвейером;
отдельная тяжёлая модель и платный API не нужны. Биография, рекламные контакты
и регистрационные сведения не являются достаточным основанием назначения.
При противоречиях остаётся `unknown` с кандидатами и причинами.

Это **гибридный исследовательский метод**, не обученная на независимой
географической разметке модель. Эвристические баллы и cosine scores не являются
вероятностью правильности. Географические предложения также требуют проверки.
Сильные совпадения заголовка всё ещё используют правила, но простое наличие
названия в любом посте больше не является единственным решением.

Справочник включает 257 названий стран/территорий CLDR и все 89 региональных
записей существующего проекта. Это полнота списка доступных идентификаторов,
**не гарантия распознавания любого написания, города или канала**. Подсказки по
городам дополняемы; полный мировой каталог городов и NER здесь не заявляются.
Состав регионов унаследован от проектных данных и не является отдельным
утверждением о международно-правовом статусе спорных территорий.

Названия стран: Unicode CLDR 48, Unicode-3.0; URL и SHA-256 исходников записаны
в `config/countries_v11.json`, уведомление — `docs/licenses/UNICODE.txt`.
Макрорегионы, организации и псевдолокали CLDR исключены из стран. Зарубежные
городские подсказки — отдельный курируемый файл; за пределами РФ результат
всегда сводится к стране. При обновлении исходников:

```powershell
# Только открытые справочники Unicode, не Telegram:
python scripts/prepare_classification_geography.py
python scripts/sync_classification_v11.py
```

## Ресурсы и безопасность

Нужны `requirements-classification.txt` и заранее доступный локально E5-small.
Существующее окружение проекта уже подходит. Во время классификации веса не
скачиваются; изменения названия модели/ревизии нельзя маскировать кешем.
Первый прогон по нескольким тысячам каналов с постами может занимать десятки
минут — прежний замер 135 секунд относился к одним профилям и сюда не переносится.
Повторный прогон использует SQLite-кеш embeddings. Новый сбор/обучение не
запускаются из экспортера, API или браузера.

БД используется только в read-only session. Сборщик не меняет новости,
watermarks, старые модели и рабочие JS/JSON. Публикация сохраняет предыдущий
кеш отдельным архивом; несовместимые таксономии и повреждённые результаты
отклоняются до записи. HTML и реальные кеши остаются локально, вне Git.

Для возврата к прежней основе отключите `enabled` в политике V11, выполните
`sync_classification_v11.py`, перезапустите API и повторите явный экспорт.
Это не удаляет результаты эксперимента и ручные ответы.

Проверки реализации: 284 Python-теста без ошибок (38 условных пропусков),
Ruff и браузерные сценарии основной карты и автономного просмотра прошли.
Локальный smoke-test на трёх прежних пилотных каналах использовал восемь
постов, дал ожидаемые темы авиации/афиши/налогов и около 860 МБ peak working
set. Это проверка исполнения, не независимый замер точности географии или тем.
