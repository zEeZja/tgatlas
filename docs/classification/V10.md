# V10 — локальные смысловые предложения

Пересмотр самих тематик и пилот по публикациям описаны отдельно:
[гибридный черновик V11](TAXONOMY_V11.md). Он не заменяет текущие темы V10
и не мигрирует ручные ответы автоматически.

## Статус

Экспериментальный конвейер рядом с V9, **не замена рабочей классификации**.
Требование высокой точности пока не подтверждено. Автоматические назначения
отключены результатом калибровки: `insufficient_calibration`.
Отказ от всех назначений не считается высокой точностью.

Все 63 содержательные темы доступны через положительные смысловые определения
из `config/zero_shot_labels.json`. Подтверждённые примеры дополняют определения,
но не ограничивают набор классов. `other` — отказ/неопределённость, не смысловой
прототип. Scores — относительные оценки или логиты, **не вероятность правильности**.

## Архитектура

1. Очистка профиля; пакетные локальные embeddings с фиксированной ревизией весов.
2. Смысловые прототипы всех тем; few-shot retrieval либо линейная голова,
   обученная одновременно на train-примерах и прототипах.
3. Выбор алгоритма, весов, регуляризации и балансировки по пяти train-OOF folds.
4. Подбор рабочего порога по train OOF: precision ≥95% минимум на 15 примерах.
   Это исследовательская оценка, не независимая гарантия; редкие классы
   дополнительно требуют не менее трёх train-примеров.
5. При сомнениях допускаются только имеющиеся локальные снимки постов,
   по умолчанию максимум 100 каналов и четыре публикации на канал. HTTP выключен.
6. Отдельные предложения темы и географии; ручные ответы сохраняют независимый
   приоритет. Ручная тема не требует encoder. Экспорт/API читают готовый кеш,
   а не запускают модель. Браузер не принимает предложения за подтверждения.

SQLite-кеш хранит нормированные float32-векторы без pickle. Ключ включает текст,
модель, ревизию, pooling, префикс, точность и token limit. Размер пакета и число
потоков не инвалидируют кеш. Повреждённый вектор пересчитывается. Веса читаются
локально через safetensors, без remote code и автоматического скачивания.

## Сравнение на разметке владельца

72 уникальных тематических train-профиля, 22 исторических test-профиля.
Train не содержит `crypto`, `economics`, `marketing`, `taxes`.
Test ранее многократно использовался для диагностики: это **не новый независимый
контроль** и не оценка точности всех 3000 каналов. Параметры выбирались по train OOF.

| Прежние правила | — | 11/22 | — | — |
| V9.2, локальный сохранённый отчёт | — | 12/22 | — | — |

¹ Полное время CLI, включая импорты и загрузку модели, на Intel i3-10100,

Выбранная голова: balanced logistic regression, C=10, вес прототипа=1.
Ни один вариант не прошёл условие калибровки; coverage автоматических назначений
на контрольной выборке равно нулю. 15/22 недостаточно для заявления о высоком качестве.

## Запуск

### Наглядный просмотр готовых прогнозов

Откройте двойным щелчком `reports/classification-v10/view.html` — автономный
HTML, сервер и модели не нужны. Страница построена по результатам
`benchmark-small-cold.json` и соответствующему `benchmark-snapshot.json`.
На снимке 3000 каналов: 1827 расхождений и 1173 совпадения с текущей темой.
Это не число ошибок: правильность прежних тем тоже не гарантирована.

Доступны поиск, фильтры текущей/предложенной темы, расхождений и ваших оценок,
топ-5 кандидатов, причины проверки и текст, который видела модель.
Отмечайте «согласен», «V10 ошибся» или «нужны публикации / не уверен»;
при ошибке можно выбрать правильную тему и оставить комментарий.
Оценки сохраняются в localStorage этого браузера отдельно для каждого снимка.
Для надёжности нажмите **«Скачать мои оценки (JSON)»**: перенос HTML или другой
браузер может сделать локальные оценки недоступными. JSON можно загрузить
обратно только в отчёт по тому же снимку и прогнозам.
Никакие оценки не применяются к карте и не попадают в обучение автоматически.

Повторная генерация в новый файл:

```powershell
python scripts/view_classification_v10.py --output reports/classification-v10/view-next.html
```

Другие снимки задаются через `--snapshot` и `--results`. Несовпадение профилей,
неизвестные темы, повреждённые оценки и попытка заменить существующий файл
отклоняются. HTML содержит локальные данные каналов и не коммитится в Git.
Проверки страницы: `npm run test:v10-view` (Playwright; при необходимости
`CHROMIUM_PATH` указывает на установленный Chrome).

### Обучение и классификация

Из корня репозитория, в Python-окружении с numpy, sklearn, torch, transformers,
huggingface-hub и safetensors. Нужны заранее скачанные открытые веса.
Зависимости: `pip install -r requirements-classification.txt`; для CPU используйте
CPU-сборку PyTorch. Базовому сборщику эти пакеты не требуются.

```powershell
# Сначала показать размер и закреплённую ревизию; тексты каналов не отправляются.
python scripts/download_classifier_encoder.py
# Только при необходимости и с разрешённым бюджетом скачивания:
python scripts/download_classifier_encoder.py --apply

# Каждый запуск требует нового имени выходного файла.
python scripts/classify_v10.py train --review reports/classification-reviewed-merged.csv --output models/v10/small-run1.json

# Только готовый локальный снимок; карта не меняется.
python scripts/classify_v10.py classify --model models/v10/small-run1.json --input web/data/channels.json --limit 3000 --output reports/classification-v10/run1.json
```

`train --preset base|small|tiny` позволяет воспроизвести сравнение.
`--precision fp32|int8`, `--threads`, `--batch-size`, `--cache` управляют ресурсами.
`classify --database` читает БД в read-only session. Лимит времени запрещает
постановку следующего блока из 64 каналов, но не прерывает текущий forward.
При остановке отчёт содержит число оставшихся каналов.

`train --post-cache reports/classification-samples` явно разрешает замороженные
исторические посты для обучения. Общие репосты исключаются между профилями,
как и дубли профилей между train/test. Такие снимки не объявляются свежими.
`classify --post-cache ...` использует только свежий локальный кеш с TTL 24 часа.
Свежесть профиля и постов повторно проверяется при слиянии с экспортом.

Только явный `classify --apply` публикует кеш предложений в
`reports/classification-v10/catalog.json`; это не подтверждение и не ручная
переразметка. Перед публикацией проверяются тема, группа, таксономия и конечность
чисел; запись атомарная. Не публикуйте текущую экспериментальную модель массово.

Веса, кеши и реальные отчёты остаются локальными и не входят в Git.
В этой работе скачан только новый E5-base: 1 134 354 391 байт, MIT,
revision `d128750597153bb5987e10b1c3493a34e5a4502a`.
E5-small и RuBERT-tiny2 уже имелись локально. Новые NLI-веса не скачивались.
Помощник скачивания проверяет размер одного набора файлов; общий разрешённый
бюджет нескольких моделей следует учитывать отдельно.

## Следующий барьер качества

Нужна новая независимая стратифицированная разметка, особенно редких и соседних
тем. Компактный NLI-reranker shortlist остаётся гипотезой, не реализованным
улучшением. Сначала нужен ограниченный train-OOF probe с учётом recall top-5,
времени, памяти и остатка бюджета, без подстановки ожидаемой темы в shortlist.
Старые модели V9 и эксперименты V10 сохранены.

## Проверки

`python -B -m unittest discover -s tests -q`: 258 тестов, ошибок нет,
38 пропущены по условиям окружения. Новые проверки покрывают кеш и его
повреждения, полную таксономию, отсутствие влияния test-меток на обучение и
пороги, ручной приоритет, отказ при нехватке калибровки, проверку артефакта,
атомарную публикацию и независимость темы/географии.
`node tests/frontend.cjs` прошёл с установленным Chrome: предложения V9/V10,
экранирование evidence, фильтры и карточки; ошибок JavaScript нет. Ruff прошёл.
