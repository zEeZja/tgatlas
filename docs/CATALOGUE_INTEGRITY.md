# Целостность каталога и свежесть метаданных

## Безопасное обновление БД

Перед `python main.py init-db` сделайте резервную копию через `pg_dump -Fc`.
Миграции `0003` и `0004` применяются одной транзакцией. Не изменяйте уже
применённые SQL-файлы. Проверка без записи: `python main.py db-status`.

`0003` объединяет записи `channels`, username которых отличается только
регистром. Сохраняется самый старый внутренний `id`, username приводится к
нижнему регистру. При разных известных Telegram ID миграция останавливается
без частичного объединения: такие случаи требуют ручной проверки.

При объединении:

- оригинальные каналы, посты, источники, курсоры и связанные кандидаты
  сохраняются в `channel_merge_archive.records` (JSONB);
- посты объединяются по Telegram message ID; при конфликте сохраняются более
  свежие известные текст/заголовок и максимальный счётчик просмотров;
- уникальные посты сохраняют свои внутренние ID; конфликтующие версии остаются
  в архиве;
- ссылки кандидатов перенаправляются на оставшийся канал, источники объединяются;
- курсор покрывает объединённый интервал с допустимым повторным чтением;
- название, описание и аудитория предпочитаются из более свежей проверки;
  пустое подтверждённое описание не подменяется старым;
- если хотя бы одна запись была неактивна, объединённая запись не активируется
  автоматически. Это консервативная защита ручного отключения.

В БД действуют ограничение нижнего регистра и уникальный индекс `lower(username)`.
Прямой SQL с username в смешанном регистре отклоняется; импорт должен использовать
`src.identity.normalize_username`. Экспорт и браузер дополнительно отклоняют
дубли, а не молча удаляют их.

Архив не является заменой внешней резервной копии. Для полного отката нужно
восстановить dump в отдельную БД и переключить приложение на неё по инструкции
[DATABASE.md](DATABASE.md). Не удаляйте архив сразу после обновления.

## Обновление по свежести

```bash
python main.py refresh-metadata --workers 2
python main.py refresh-metadata --max-age-hours 24 --retry-after-hours 1 --limit 100
python main.py refresh-metadata --channel breakingmash --force --workers 1
python main.py export
```

По умолчанию обновляются метаданные старше **24 часов** и записи без даты проверки.
После неудачной попытки действует пауза **1 час**. Сначала обрабатываются записи
без даты, затем самые старые. `--limit` ограничивает одну партию. `--force`
игнорирует свежесть и паузу ошибок, но не глобальный ограничитель запросов Telegram.
Явный `--channel` без `--force` также учитывает свежесть.

Состояние хранится в БД и переживает перезапуск: успешно обновлённые записи не
опрашиваются повторно до истечения срока. Несколько одновременно запущенных
процессов не координируют выборку между собой; запускайте один планировщик.

- `last_meta_at` — последняя полная успешная проверка названия, описания и аудитории;
- `last_meta_attempt_at` — последняя попытка, в том числе неудачная;
- `last_meta_error` — безопасный код ошибки, без SQL, паролей и текста исключений;
- `last_parsed_at` — обход публикаций, **не** показатель свежести аудитории;
- `generated_at` — создание выгрузки, **не** проверка каналов.

Ошибка не обнуляет прежние метаданные и не переносит дату успешной проверки.
Частичный ответ может дополнить известные поля, но не делает весь профиль свежим.
Следующая полная успешная проверка очищает ошибку. Пропуск всех свежих записей
считается успешным запуском; неизвестный явно выбранный канал остаётся ошибкой.

Интерфейс показывает дату проверки в карточке, последнюю ошибку и общие количества
свежих, устаревших и непроверенных каналов. Порог интерфейса — 24 часа. Изменение
`--max-age-hours` меняет частоту опроса, а не критерий отображения. Даты старого
каталога не выдумываются и не заменяются датой применения миграции.

## Публикация

При HTTP-загрузке основной источник — атомарно заменяемый `channels.json`.
Он запрашивается без использования HTTP-кеша; старый JS-снимок его не затеняет.
`channels.js` загружается только при `file://`. Отсутствующий HTTP JSON даёт явно
помеченный демокаталог, а повреждение JSON, дубли и ошибка сервера — сообщение об
ошибке. Атомарность пары JSON/JS не обещается: при ошибке экспорта повторите команду.
