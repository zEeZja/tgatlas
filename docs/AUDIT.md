# Аудит стабильности и оптимизации

Дата проверки: 11 ноября 2026. Основа: ветка `frontend/atlas-redesign`, коммит `2b9416f`. Цель — исправления и уборка существующего поведения. Новые продуктовые функции перечислены отдельно в [плане для согласования](ROADMAP.md).

## Исправлено

| Область | Найденная проблема | Изменение |
|---|---|---|
| Повторный сбор | Конфигурация могла перезаписать уже актуальные имя, рубрики и другие поля перед сетевым обновлением | Первичное заполнение добавляет только отсутствующие username, включая учёт неактивных записей |
| Транзакции | SQL-ошибка метаданных перехватывалась внутри транзакции, оставляя PostgreSQL в состоянии aborted | Разбор HTML вынесен до транзакции; ошибка SQL откатывает канал, посты и курсор |
| Автоматизация | Частичная ошибка `scrape` не давала ненулевой код завершения | Возвращается статистика; CLI завершает неуспешный/пустой запуск кодом 1 |
| Выбор каналов | Явно указанный отсутствующий канал мог молча дать пустую обработку | Явная ошибка неизвестного канала для обоих публичных режимов |
| Инкрементальный обход | Повреждённый HTTP 200 без постов принимался за конец участка | Проверка метаданных пустой страницы; при ошибке курсор не очищается |
| HTTP-запросы | Username и `before` принимались без локальной проверки | Некорректные идентификаторы/курсоры отклоняются до сети |
| Парсер | Неположительный ID поста мог попасть в обработку | Невалидные ID пропускаются |
| Выгрузка | Прямое перезаписывание файла позволяло прочитать недописанный JSON/JS | Полная запись во временный файл рядом, fsync и os.replace, очистка временного файла при ошибке |
| Загрузка карты | Демокаталог мог затенять реальный JSON и загружался даже при наличии рабочих данных | Демо загружается лениво только при отсутствии выгрузки; повреждённые данные и HTTP 500 показываются как ошибка |
| Ссылки карточки | Каталог мог задать произвольную схему URL | Telegram-ссылка строится из проверенного username |
| Настройки | Неверный/пустой необязательный числовой Telegram-параметр мешал базовым командам | Валидация обязательных чисел; безопасные значения по умолчанию для необязательных настроек; .env привязан к корню |
| API | Версия расходилась с VERSION | Единственный источник версии — файл VERSION |
| ML-режим | t-SNE падал при малом числе каналов из-за perplexity >= n_samples | Perplexity ограничена размером выборки; 1–2 точки размещаются без загрузки модели |

Атомарность относится к **одному файлу**, а не к паре JSON/JS. Если запись второго файла не удалась, команда сообщает ошибку; перед использованием выгрузки повторите экспорт. Гарантия также зависит от поддержки атомарной замены файловой системой. Распознанный корректный, но действительно пустой канал по-прежнему завершает участок обхода.

## Оптимизировано

- Правила ручных тем, географии и федерального охвата читаются **3 раза на пакет**, а не по 3 чтения на канал. Регрессионный тест проверяет 100 каналов и ровно 3 чтения. JSON-таксономия по-прежнему загружается при старте процесса; после её изменения нужен перезапуск API.
- Состояние видимых облаков Canvas вычисляется за один проход по точкам через Set. Убраны повторные `filter`/`some` по всему массиву для каждого облака: участок стал O(N+C) вместо O(N×C). Это оценка сложности данного участка, не обещание определённого FPS.
- Запрос максимальных ID постов ограничивается выбранными каналами; пустой список не сканирует таблицу постов.
- Сохранены ограниченный пул сетевых загрузчиков, единый ограничитель частоты, повторное использование HTTP-сессий и пакетная запись с дедупликацией. Увеличивать параллелизм без контроля ограничений Telegram не требуется.

## Уборка

Удалены неиспользуемая приватная функция `_scrape_channel`, пустой словарь `TOPIC_EMOJI`, неиспользуемые импорты/переменные и неиспользуемая заглушка `web/data/geo_map.js`. Сам старый географический режим сохранён: он остаётся публичной CLI-командой и API.

Изменённые Python-файлы отформатированы Ruff; исправлены статические ошибки F/E9. Добавлены настройки линтера, отдельный requirements-dev, шаблон .env и актуальное руководство запуска. Старые инструкции, аудит и CSV-снимки перенесены в `docs/history`, чтобы сохранить уникальные данные. Генерируемые рабочие отчёты и кеш линтера исключены из Git. Пользовательская БД, локальные выгрузки и конфигурация каналов не очищались.

Существующие 8 диаграмм сохранены; пояснения дополнены новым поведением загрузки, транзакций и повторного импорта. Ещё одна схема тех же потоков не нужна.

Базовая проверка до изменений: **76 Python-тестов**. После исправлений добавлены регрессионные проверки атомарной записи, чтения правил, сохранности метаданных, отката SQL, ошибочных ответов, параметров запроса, API и кода завершения CLI. Контрольный прогон:

Дополнительно офлайн обработана локальная выгрузка **1042 каналов**: результаты классификации при загрузке правил на каждую запись и при общем снимке совпали. В одном прогоне получено 5,13 и 3,33 секунды соответственно; это локальное наблюдение с прогретым кешем, а не воспроизводимый бенчмарк или обещание ускорения в продакшене. Выгрузка при проверке не переписывалась. Проверка геометрии использует синтетический расширенный набор, а не только демокаталог.

Проверки БД здесь используют подменённые подключения; отдельного работающего PostgreSQL в среде нет. Это **не проверка SQL на реальной базе**, миграции пользовательской базы или восстановление из backup. Не выполнялись авторизация Telethon, сетевой сбор всего каталога и загрузка ML-модели. Эти ограничения не позволяют обещать отсутствие всех ошибок.

Точность классификации нельзя подтвердить только тестами на подобранных примерах: необходим размеченный контрольный набор из реальных каналов. Работа с ним вынесена в согласуемый план. Фикстуры и проверки совпадения Python/JavaScript сохранены.
