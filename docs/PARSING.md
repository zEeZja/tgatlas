# Парсинг и расширение каталога

Все команды ниже запускаются **из корня проекта**. Нужны Python 3.10+,
PostgreSQL и зависимости из `requirements/locked-base.txt`.
Для основного сборщика не нужны Telegram-аккаунт, `api_id/api_hash` или TGStat.

## 1. Выберите нужный режим

| Задача | Команда |
|---|---|
| Найти, проверить и добавить **новые каналы** по приоритетам | `python scripts/grow_catalog.py --apply` |
| Обновить устаревшие название, описание и аудиторию существующих каналов | `python main.py refresh-metadata --workers 2` |
| Собрать **публикации**, а не новые каналы | `python main.py scrape --workers 2 --pages 5` |
| Пересоздать файлы для карты из БД | `python main.py export` |
| Посмотреть статистику кандидатов | `python main.py candidate-stats` |

`grow_catalog.py` проверяет только публичные профили `https://t.me/username`.
Публикации и подписки аккаунта он не читает и не изменяет.

## 2. Настройка и резервная копия

Установка и первоначальное создание БД описаны в [README](../README.md).
Если `.env` уже настроен, **не заменяйте его** файлом `.env.example`.

Проверьте настройки:

```dotenv
PG_HOST=127.0.0.1
PG_PORT=5432
PG_USER=postgres
PG_DATABASE=tg_parser
# PG_PASSWORD задаётся локально; не публикуйте его.
MIN_CHANNEL_SUBSCRIBERS=1000
SCRAPE_REQUEST_INTERVAL=1.0
```

Перед первым импортом или обновлением схемы сделайте свежую копию. Например:

```powershell
pg_dump -h 127.0.0.1 -U postgres -d tg_parser -Fc -f atlas-before-growth.dump
pg_restore --list atlas-before-growth.dump
python main.py db-status
```

Подставьте свои параметры подключения. `pg_dump` сам не читает проектный `.env`:
он запросит пароль либо использует штатные настройки PostgreSQL (`pgpass` и т. п.).
Если команда не найдена, укажите полный путь к PostgreSQL `bin`.
`--list` проверяет читаемость архива, но не заменяет пробное восстановление.

При ожидающих миграциях сначала прочтите [DATABASE.md](DATABASE.md), затем
выполните `python main.py init-db`. Сборщик сам миграции **не применяет**.
Не восстанавливайте дамп поверх работающей БД ради обычного продолжения сбора.

## 3. Посмотреть план без записи

```powershell
python -B scripts/grow_catalog.py
```

Команда показывает текущий размер, целевой размер, недостающее количество,
порог аудитории и число заданий. **Это просмотр плана, не сетевой поиск**:
никакие источники не запрашиваются, кандидаты и каналы не записываются.

План находится в [`config/catalog_growth.json`](../config/catalog_growth.json):

- приоритетные темы: кредитование, банки, госвласть, промышленность, ВПК,
  космическая отрасль, авиастроение, ТЭК, транспорт и его направления;
- смежные финансовые темы: бизнес, инвестиции, личные финансы, экономика, налоги;
- поисковые запросы, предел страниц поиска и каталоги;
- явный список официальных страниц со ссылками на Telegram.

Смежные темы учитываются отдельно в отчёте по темам; это не означает, что
инвестиционный канал автоматически считается банком или кредитной организацией.
Поисковые задания чередуют разные приоритетные отрасли, а не ищут только банки.

## 4. Пробная партия

Сначала ограничьте число проверок:

```powershell
python -B scripts/grow_catalog.py --apply --target 3000 --max-profiles 30 --max-requests 100 --max-minutes 10 --workers 2
```

Это настоящий импорт прошедших фильтры каналов, а не preview. Пределы позволят
проверить небольшой объём и остановиться. `--target` — **общий размер активного
каталога**, а не число новых каналов. Если текущий размер уже не меньше цели,
новые каналы не добавляются.

Сохранённое состояние продолжайте использовать в основном запуске:

```powershell
python -B scripts/grow_catalog.py --apply --target 3000 --workers 4 --max-profiles 12000 --max-requests 24000 --max-minutes 180
```

Без `--allow-other` допускаются только приоритетные и перечисленные смежные
финансовые темы. Каналы иных тематик откладываются, даже если найдены в рубрике
«Экономика» или по отраслевому запросу.

### Что означают ограничения

| Параметр | Значение по умолчанию | Смысл |
|---|---:|---|
| `--target` | 3000 | Желаемый общий размер активного каталога |
| `--workers` | 4 | Сетевые потоки, от 1 до 8; SQL-запись последовательная |
| `--max-profiles` | 6000 | Новые проверки профилей за запуск; внутренние HTTP-повторы Telegram отдельно |
| `--max-requests` | 12000 | Запросы к сайтам-источникам, включая robots и карточки; не запросы Telegram |
| `--max-minutes` | 180 | Время до прекращения постановки новых задач; начатые запросы завершаются |
| `--state` | `reports/catalog-growth/state.json` | Контрольная точка и результаты |
| `--plan` | `config/catalog_growth.json` | JSON-план источников и приоритетов |
| `--log` | Не задан | Дополнительный журнал UTF-8, дополняемый при повторном запуске |

Четыре потока не означают четыре запроса к Telegram каждую секунду:
работает общий ограничитель `SCRAPE_REQUEST_INTERVAL` и общие паузы при 429.
Источники ограничены минимум одним запросом в секунду на хост; учитываются
также `Crawl-delay` и `Request-rate` из robots.txt. Большая партия может идти часы.

Не запускайте одновременно второй сборщик, `scrape` или `refresh-metadata`:
ограничитель Telegram общий для потоков **одного процесса**, не всей машины.
Два процесса `grow_catalog.py` дополнительно защищены блокировкой PostgreSQL.

## 5. Состояние, журнал и продолжение

В другом терминале можно прочитать последний сохранённый итог:

```powershell
python -B scripts/grow_catalog.py --status
python -B scripts/grow_catalog.py --status --state reports/catalog-growth/state.json
```

Значимые поля:

- `current_count` — число активных каналов на момент сохранения;
- `total_imported` — реально импортированные каналы данного состояния, с учётом
  всех продолжений; это не число найденных ссылок;
- `imported_topics` и `imported_sources` — распределение именно импортированных;
- `this_run` — исходы последнего/текущего запуска, не общий итог;
- `updated_at` — время сохранения; `running` само по себе не доказывает, что
  процесс ещё жив после аварийного завершения.

В полном JSON дополнительно есть завершённые задания/страницы, отложенные
результаты, ошибки источников и очередь временных ошибок `retry_cards`.
Контрольная точка сохраняется после страницы и каждых 10 завершённых результатов.
Записанные в БД каналы защищены от дублей даже при потере последних изменений
контрольной точки. Итоги импорта восстанавливаются из БД по идентификатору запуска.

| `status` | Что делать |
|---|---|
| `target_reached` | Цель достигнута, код завершения 0 |
| `budget_exhausted` | Исчерпан один из лимитов; повторить команду с тем же `--state` |
| `paused_for_retry` | Проверить ошибки; после паузы повторить команду |
| `sources_exhausted` | Все задания выбранного плана исчерпаны, цель пока не достигнута |
| `interrupted` | Запуск прерван; продолжить с той же контрольной точкой |

Для незавершённого применённого запуска код завершения — **1**. Это может означать
штатный бюджет, а не повреждение БД. Не запускайте бесконечный цикл немедленных
повторов при 403/429. Ограничения доступа не обходятся.

Для журнала UTF-8, не зависящего от кодировки PowerShell:

```powershell
$env:PYTHONUTF8 = "1"
python -B scripts/grow_catalog.py --apply --target 3000 --log reports/catalog-growth/manual-run.log
```

Не используйте этот же файл для двух одновременных запусков. Во время текущего
автоматического сбора журнал находится в `reports/catalog-growth/growth-run.log`.
Для остановки используйте Ctrl+C один раз и дождитесь завершения начатых задач.

### Если нужно изменить план

Повтор с тем же планом и `--state` пропускает завершённые задания и обработанные
username, повторяет временные ошибки. Незавершённый хвост страницы не теряется.
Кандидаты, оставшиеся подходящими после достижения маленькой пробной цели,
могут быть повторно проверены при увеличении цели.

При изменении плана или порога аудитории используйте **новый файл состояния**:

```powershell
python -B scripts/grow_catalog.py --plan config/catalog_growth.json --state reports/catalog-growth/next-state.json
python -B scripts/grow_catalog.py --apply --plan config/catalog_growth.json --state reports/catalog-growth/next-state.json --target 3500
```

Не редактируйте хеш в старом состоянии. Новый `--state` также нужен для
повторного обхода уже завершённых страниц после существенного обновления
источников/правил классификации. Известные каналы при этом не перезаписываются.

## 6. Как допускается канал

1. Из списка извлекается основная карточка. Контакты рекламодателей,
   похожие каналы, рекламные блоки, боты и приватные приглашения не импортируются.
2. Username нормализуется; существующие записи, в том числе неактивные,
   не обновляются и не активируются этим сборщиком.
3. Загружается актуальный публичный профиль Telegram. Нужны название,
   описание (оно может быть пустым) и известное число **подписчиков канала**.
   Личные профили и группы с числом участников не подходят.
4. Применяется `MIN_CHANNEL_SUBSCRIBERS`, по умолчанию 1000. Старая цифра
   аудитории из каталога не заменяет проверку Telegram.
5. Тема определяется из профиля и действующих правил/ручных подтверждений,
   **не из поискового запроса или чужой рубрики**. Неоднозначные результаты,
   отметки SCAM/FAKE и выявленные рискованные предложения откладываются.
6. Подходящий канал добавляется одной транзакцией вместе со связью кандидата
   и источником. Разрешены только вставки новых каналов; `ON CONFLICT` ничего
   не перезаписывает. Проверка перед импортом не старше часа.

Тематика остаётся автоматическим предварительным назначением, а не ручной
сертификацией. Риск-фильтр также не гарантирует отсутствие любого мошенничества.
Отложенные темы/неоднозначности остаются кандидатами `pending`, низкая аудитория —
`rejected`; успешный импорт — `imported`. Непубличные ссылки и сетевые ошибки
видны в состоянии сборщика, но не обязаны создавать строку кандидата в БД.

### Остальные тематики — только потом

После завершения всех предусмотренных планом приоритетных заданий можно явно
разрешить следующий этап:

```powershell
python -B scripts/grow_catalog.py --apply --target 3000 --allow-other
```

Если приоритетная фаза ещё не завершена, сначала продолжится она. Пока у неё
остались незавершённые задания или временные ошибки, остальные темы не запускаются.
Речь о завершении **ограниченного плана**, а не об исчерпании всех каналов Telegram.
Отложенные неприоритетные темы перед импортом снова проверяются через Telegram.
Неоднозначные и рискованные записи этим флагом автоматически не разрешаются.

## 7. Источники и их ограничения

| Источник | Использование |
|---|---|
| TgramSearch | Публичный `/search?query=…`, категории и основная ссылка карточки `/join/…` |
| tlgrm.ru | Прямые публичные username обычных карточек; рекламные перенаправления не обходятся |
| Официальные сайты | Только Telegram-ссылки на явно перечисленных страницах, без рекурсивного обхода |
| TGStat API | Отдельная существующая команда, только с вашим токеном и доступным тарифом |
| TXT/CSV/JSON-списки | Отдельный импорт кандидатов из законно полученного файла |

У TgramSearch запрос через `/?query=…` не является поиском. У tlgrm путь
`/channels/economics` на практике означает **политику**, не экономику: название
пути нельзя использовать как готовую разметку.

Сборщик проверяет robots.txt, использует ограниченный кеш и прекращает запросы
к хосту при HTTP 401/403/429. CAPTCHA, авторизация, платный доступ и частные API
не обходятся. Недоступный официальный сайт не мешает другим доступным источникам,
но не считается успешно пройденным приоритетным заданием.

В ходе проверки TGStat HTML отвечал 403, токен API не был настроен. Telemetrio
скрывает username за Pro: восстанавливать эти данные из URL не следует.
Существующий адаптер tgden остаётся в проекте, но его suggest даёт мало результатов,
а robots.txt закрывает `/api/` для обхода; новый массовый сбор его не использует.

Для дополнительного расширения полезны открытые списки министерств и региональных
ведомств, пресс-центры банков/холдингов, отраслевые ассоциации, аэропорты,
перевозчики и публичные наборы данных с разрешающими условиями использования.
Сначала проверяйте условия доступа, потом добавляйте страницу в `official_pages`
или используйте файловый импорт. Страницы должны быть общедоступными HTTPS.

### Отдельный TGStat API

После настройки `TGSTAT_API_TOKEN` в `.env` и проверки своего тарифа:

```powershell
python main.py discover-tgstat --query "банки" --search-by-description --limit 100
python main.py candidate-stats
```

Эта команда создаёт кандидатов, **не выполняет автоматический приоритетный импорт**.
Параметры и актуальные ограничения: `python main.py discover-tgstat --help`.

### Импорт собственного списка

TXT-файл содержит по одному `@username` или публичной ссылке `https://t.me/username`
на строку. Доступны также CSV, TSV и JSON:

```powershell
python main.py import-candidates --file channels.txt --source-name industry_list
python main.py import-candidates --file channels.txt --source-name industry_list --apply
python main.py discover-validate --limit 100
python main.py candidate-list --status validated --limit 100
python main.py candidate-import --username checked_channel
python main.py candidate-import --username checked_channel --apply
python main.py export
```

`checked_channel` замените конкретным проверенным username. Это отдельный ручной
маршрут: отраслевой фильтр `grow_catalog.py` здесь не действует. Не используйте
массовый `candidate-import --include-pending` для достижения цели: так можно
импортировать отложенные неподходящие темы. Старые команды импорта могут обновлять
существующие записи; insert-only гарантия относится именно к новому сборщику.

## 8. Экспорт и просмотр

Сборщик автоматически пересоздаёт `web/data/channels.json` и `channels.js`
после каждых 50 импортов текущего запуска и при штатном завершении. Если процесс
был прерван, для немедленного отображения записанного в БД выполните:

```powershell
python main.py export
python -m http.server 4173 --directory web
```

Откройте `http://localhost:4173` и обновите страницу с очисткой кеша. Экспорт
применяет правила классификации, но не записывает автоматическую тему в ручные
подтверждения. Сам факт генерации файла не означает свежей проверки всех старых
каналов; новый сборщик проверяет только новые профили.

Последующие обновления существующей базы можно ограничить по свежести и размеру:

```powershell
python main.py refresh-metadata --max-age-hours 24 --retry-after-hours 1 --limit 100 --workers 2
python main.py refresh-metadata --channel centralbank_russia --force --workers 1
python main.py export
```

Сначала обрабатываются записи без даты проверки, затем самые старые. По умолчанию
свежие данные моложе 24 часов не запрашиваются; после ошибки действует пауза 1 час.
`--force` отключает эти два условия, но не ограничитель HTTP-запросов. Неудача
сохраняет прежние поля и дату успешной проверки; в БД записывается безопасный код
ошибки. В карточках и сводке свежесть считается по `last_meta_at`, не по времени
экспорта. Подробнее: [CATALOGUE_INTEGRITY.md](CATALOGUE_INTEGRITY.md).

`.env`, сессии, дампы, кеши и `reports/catalog-growth/` не публикуются в Git.
`channels.json` исключён из Git; `channels.js` исторически отслеживается в этом
репозитории и может содержать публичный снимок каталога. Рабочая PostgreSQL-база
в Git не переносится: для переноса нужны отдельно настройки и резервная копия.

## 9. Проверки разработчика

```powershell
python -m unittest tests.test_public_catalogues tests.test_catalog_growth
python -m ruff check src/public_catalogues.py src/catalog_growth.py scripts/grow_catalog.py
```

Тесты реального SQL запускайте только на отдельной временной БД через явно заданный
`ATLAS_TEST_DSN`, не подставляя в него рабочую базу:

```powershell
python -m unittest tests.integration.test_catalog_growth
```

В них сетевые ответы подменены, но вставки, транзакции, защита существующих каналов,
возобновление и ограничения импорта проверяются настоящим PostgreSQL.

Перед публикацией также восстановлена согласованность планировщика свежести,
полей экспорта и тестов миграций с текущей схемой `0004`. Применённые SQL-миграции
при этом не переписывались. Полный PostgreSQL-прогон: `python scripts/run_postgres_tests.py`
с отдельной тестовой БД. Проверки браузера: `npm run test:freshness`,
`npm run test:layout`, `npm run test:frontend`, `npm run test:review`.
