# Дубли и свежесть: результат доработок 12 ноября 2026

## Рабочая база

Перед обновлением создана резервная копия
`atlas-before-identity-20261112T072301Z.dump` (23 819 457 байт).
Предварительно более ранняя копия была восстановлена в отдельную временную БД,
к ней применены миграции и проверена сохранность уникальных постов и источников.

К рабочей БД применены миграции `0003` и `0004`:

| Показатель | До | После |
|---|---:|---:|
| Записи каналов | 1042 | 971 |
| Уникальные username без учёта регистра | 971 | 971 |
| Посты | 77613 | 76541 |
| Уникальные пары username/message ID | 76541 | 76541 |

1072 повторных записи постов объединены; уникальные публикации не потеряны.
Все уникальные связи каналов с источниками сохранены. 71 группа объединения
сохранена в `channel_merge_archive`: 142 исходных канала и 6816 исходных записей
постов вместе с источниками, курсорами и связанными кандидатами.

Оба файла `web/data/channels.json` и `channels.js` пересозданы, содержат 971
уникальный активный канал и совпадающие данные. У всех каналов экспортирована
существовавшая в БД дата `last_meta_at`. Новые даты попыток не выдумывались:
на момент обновления `last_meta_attempt_at` пуст у всех исторических записей.
Новый сетевой опрос Telegram не выполнялся.

## Поведение

- Новые дубли по регистру запрещены в БД; экспорт и браузер проверяют уникальность.
- Метаданные обновляются по свежести: 24 часа, пауза после ошибки 1 час,
  старые записи первыми, есть ограничение партии и принудительный повтор.
- Успешная проверка, попытка и ошибка хранятся отдельно; частичный ответ не
  переносит дату полной успешной проверки.
- Карточка и сводка показывают свежесть; дата экспорта не выдаётся за дату проверки.
- При HTTP используется один JSON-снимок без HTTP-кеша; JS нужен только для file://.
- Правила и алгоритмы классификации не изменялись. Их применение при обычном
  экспорте сохраняется; оценка точности классификации остаётся отдельной задачей.

## Проверки

- 27 интеграционных тестов с настоящим PostgreSQL — успешно, без пропусков;
  использовалась отдельная созданная для прогона временная база.
- Chromium: демо, API, JSON, фильтры, карточки, мобильные размеры, новые статусы
  свежести, ошибка обновления, защита от старого JS и повторных username — успешно.
- Геометрия: 2200 точек, оба режима, детерминированность, hit-test — успешно.
- Проверки JavaScript-модуля свежести — успешно.
- `ruff check .` — успешно.
- `db-status` и проверка готовности схемы — версия `0004`, ожидающих миграций нет.

В общем модульном прогоне остаётся ранее обнаруженное падение
`test_browser_taxonomy_is_in_sync`: побайтное сравнение координат расходится на
погрешности около `2.22e-16`. Географические словари и сгенерированная таксономия
ради обхода этой проверки не переписывались. Этот тест не является свидетельством
новой ошибки классификации, но общий прогон пока не полностью зелёный.
