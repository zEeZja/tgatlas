# Сбор постов через RSSHub

Это альтернативный транспорт **шага 6** [расширения карты](GROWTH_6000.md).
Он собирает выборки для классификации, а не полную историю и не новые каналы.
Посты записываются в тот же `<run>/posts/*.json`; 11v2 и t-SNE менять не нужно.
Старый прямой `--http` сохранён, по умолчанию сбор по-прежнему локальный.

## Без Docker: использовать внешний RSSHub

Docker/WSL/виртуализация на вашем компьютере **не нужны**, если уже есть доступный
удалённый RSSHub. Нужен его реальный базовый HTTPS-адрес: сборщик сам добавляет
Telegram-маршрут. Ссылку на отдельную ленту в `--rsshub-url` вставлять не нужно.
Внешний сервер должен поддерживать Telegram-маршрут и разрешать вашу нагрузку.
Публичная главная страница ещё не означает доступность Telegram-ленты.

Ограниченная проверка 23.11.2026: `https://rsshub.app/telegram/channel/telegram`
вернул HTTP 403 из этой среды. Этот адрес **не предлагается как проверенный
рабочий сервер**; автоматического поиска/ротации публичных зеркал нет.
Примеры `rss.example.org` ниже — заглушка, не действующая услуга.

### Если localhost не запускался и состояние содержит rsshub_unavailable

Существующий run не удаляйте. После получения рабочего адреса:

```powershell
$RssHub = 'https://rss.example.org' # ЗАМЕНИТЕ на реальный разрешённый сервер
python -B scripts/classify_catalog.py collect --run reports/catalog-growth-6000/posts-run-1 --rsshub-url $RssHub --change-rsshub-url --resume-rsshub --reuse-posts reports/classification-v11/catalog-run/posts --requests 3000 --hours 8
```

Подставьте свой прежний `--run`. Два флага нужны **только для первого перехода**:
`--change-rsshub-url` записывает историю старого/нового адреса и причины,
`--resume-rsshub` явно продолжает сбор. Уже использованная попытка, посты,
snapshot, общий бюджет и deadline сохраняются. Канал с потраченной попыткой
не запрашивается повторно на новом сервере. Если срок уже истёк, добавьте
`--extend-hours 8` к этой команде: смена URL сама его не продлевает.

Обычное продолжение после успешного перехода:

```powershell
python -B scripts/classify_catalog.py collect --run reports/catalog-growth-6000/posts-run-1 --rsshub-url $RssHub --reuse-posts reports/classification-v11/catalog-run/posts --requests 3000 --hours 8
```

Смена адреса разрешена только после `stop_kind: rsshub_unavailable`
(например, ConnectionError к неработающему localhost). После `rsshub_access`,
401/403/429, распознанного ограничения Telegram или исчерпания бюджета она
отклоняется **до сетевых запросов и записи состояния**. Retry-After также
не отменяется. Для нового run сразу укажите реальный `--rsshub-url`, без флагов
смены/продолжения; не создавайте run ради обхода остановки старого.

## Зачем RSSHub и насколько это быстрее

Плюсы — стандартная RSS/Atom-лента и общий кеш собственного сервера, который
можно использовать несколькими клиентами. Telegram-маршрут без аккаунта читает
те же публичные `t.me/s`-страницы. **На холодном кеше ускорение не гарантировано**;
ещё один сервер может даже добавить задержку. Ускорение от кеша зависит от того,
запрашивалась ли эта лента ранее. Замера реального RSSHub в этой среде не было.

Интеграция намеренно оставляет прежние ограничения:

- до 3000 HTTP-запросов на запуск-состояние, до 8 часов без явного продления;
- не чаще одного запроса за 6 секунд, одна попытка/одна лента на канал;
- сначала пригодный локальный кеш и БД, сеть — только при нехватке постов;
- 3–8 содержательных сообщений, до 4000 символов, публикации не старше 30 дней;
  реклама, повторы и сообщения без корректной даты отбрасываются;
- без скачивания картинок, видео, вложений, внешних статей и Telegraph;
- RSS/Atom ограничены 2 МБ и 500 записями; XML DTD и сущности запрещены;
- принимаются только ссылки на сообщения запрошенного публичного канала;
- нет автоматического перехода с RSSHub на прямой Telegram или другой сервер.

Счётчик АТЛАС учитывает запросы клиента к выбранному транспорту: после перехода —
к RSSHub. Он не измеряет внутренние повторы RSSHub и запросы других клиентов
этого сервера к Telegram; кеш также может вообще исключить обращение к Telegram.
Поэтому 3000 клиентских запросов нельзя выдавать за точное число upstream-запросов.

Маршрут: `/telegram/channel/<username>/<параметры>`. Параметры выключают
служебные сообщения, цитаты ответов, метаданные пересылок и расширение внешних
статей; сами пересланные сообщения остаются. Наличие параметров маршрута в
проверенной реализации RSSHub выбирает публичное web-превью, не MTProto.
Исходник маршрута: https://github.com/DIYgod/RSSHub/blob/master/lib/routes/telegram/channel.ts .

## 1. Собственный локальный RSSHub — необязательный вариант

Рекомендуется собственный локальный сервер, а не тысячи запросов к публичному
демонстрационному инстансу. Если RSSHub уже есть, этот шаг пропустите и используйте
его базовый HTTPS-адрес. Для HTTP разрешён только localhost/loopback.
URL не должен содержать пароль, query или fragment. Защищённые ключом в query
инстансы в этой версии не поддерживаются; не передавайте ключи через URL.

Только для этого локального варианта нужен установленный и запущенный
Docker Desktop с Linux-контейнерами. Для внешнего HTTPS-сервера он не нужен.
Из корня проекта:

```powershell
docker compose -p atlas-rsshub -f compose.rsshub.yml up -d
docker compose -p atlas-rsshub -f compose.rsshub.yml logs --tail 50 rsshub
Invoke-WebRequest http://127.0.0.1:1200/healthz
```

Дождитесь готовности сервиса. Health-check проверяет сервер, но не доступность
конкретного Telegram-канала. В `.env` проекта ничего менять не требуется.
Compose не монтирует `.env`, рабочую БД, карту или папки постов; Telegram-сессии
и `api_id/api_hash` не нужны. Порт опубликован только на `127.0.0.1`.
Redis сохраняет кеш в отдельном Docker-volume. TTL — 1 час, стандартный образ
без Chromium. Заданы лимиты памяти 768 МиБ для RSSHub и 192 МиБ для Redis;
это ограничения контейнеров, не измерение потребления и не гарантия запуска
на машине с 2 ГБ RAM: Docker Desktop/WSL потребляют память дополнительно.

По умолчанию используется `diygod/rsshub:latest`. Для воспроизводимого сервера
выберите проверенный tag/full commit SHA из
[релизов RSSHub](https://github.com/DIYgod/RSSHub/releases) и перед запуском задайте
`$env:RSSHUB_IMAGE = 'diygod/rsshub:<ваш-проверенный-tag>'`.
Образ при разработке интеграции не скачивался и контейнеры не запускались.

## 2. Если сбор постов уже идёт — продолжить тот же запуск

**Не запускайте два сборщика одновременно.** В окне старого сборщика нажмите
Ctrl+C и дождитесь выхода. Уже записанные выборки и `collection.json` остаются.
Блокировка `collector.lock` не позволяет двум процессам работать с одним run.

Ниже предполагается, что на шаге 6 вы использовали
`reports/catalog-growth-6000/posts-run-1`. Если имя другое, замените его **во всех
командах**, не создавайте новый run ради сброса бюджета.

```powershell
python -B scripts/classify_catalog.py status --run reports/catalog-growth-6000/posts-run-1
python -B scripts/classify_catalog.py collect --run reports/catalog-growth-6000/posts-run-1 --rsshub-url http://127.0.0.1:1200 --switch-to-rsshub --reuse-posts reports/classification-v11/catalog-run/posts --requests 3000 --hours 8
```

`--switch-to-rsshub` — явное разрешение сменить транспорт существующего запуска.
В `collection.json` добавляется история перехода, но **не сбрасываются**:
snapshot, deadline, requests, requests_by_channel или лимиты. Уже пригодные
выборки повторно не скачиваются. Каналы, на которые попытка уже потрачена через
прямой HTTP, также не запрашиваются заново через RSSHub. Это намеренное соблюдение
общего бюджета, а не повтор всех неудачных загрузок другим способом.
Если прежний запуск имел нестандартные `--posts`/`--requests`, укажите те же значения.

Для обычного продолжения RSSHub больше не нужен флаг переключения:

```powershell
python -B scripts/classify_catalog.py collect --run reports/catalog-growth-6000/posts-run-1 --rsshub-url http://127.0.0.1:1200 --reuse-posts reports/classification-v11/catalog-run/posts --requests 3000 --hours 8
```

Нельзя незаметно изменить экземпляр RSSHub или вернуться к `--http` в этом run.
Явный перенос после недоступности сервера описан в разделе «Без Docker» выше.
Если старый прямой сбор был остановлен по Telegram 403/429, переключение не снимает
эту остановку. Не обходите её новым run или сменой сервера.

Если истёк только срок, можно явно продлить его на 1–8 часов, не увеличивая бюджет:

```powershell
python -B scripts/classify_catalog.py collect --run reports/catalog-growth-6000/posts-run-1 --rsshub-url http://127.0.0.1:1200 --switch-to-rsshub --extend-hours 8 --requests 3000 --hours 8
```

Когда 3000 запросов уже использованы, RSSHub не получает новый бюджет. Можно
использовать собранные посты и перейти к классификации; у остальных каналов
будет анализ профиля. Не удаляйте `collection.json` и не редактируйте счётчики.

## 3. Если посты для этого снимка ещё не собирались

Только для действительно нового сбора, а не обхода остановки прежнего:

```powershell
python -B scripts/classify_catalog.py collect --run reports/catalog-growth-6000/posts-rsshub-1 --rsshub-url http://127.0.0.1:1200 --reuse-posts reports/classification-v11/catalog-run/posts --requests 3000 --hours 8
```

Без `--http`/`--rsshub-url` команда использует только локальный кеш и БД.
Эти флаги взаимоисключающие. `--no-database` отключает чтение PostgreSQL.

## 4. Диагностика и явное продолжение после сбоя RSSHub

```powershell
python -B scripts/classify_catalog.py status --run reports/catalog-growth-6000/posts-run-1
docker compose -p atlas-rsshub -f compose.rsshub.yml logs --tail 80 rsshub
```

В состоянии видны transport, rsshub_url, requests, stop_reason и retry_not_before.
Ошибки отдельных каналов находятся в `collection.json` → `channels` → `error/detail`.
Пустая/старая лента не считается достаточной выборкой. Дата загрузки RSS не
подменяет дату публикации поста. Одна страница не гарантирует разные дни.
Для Atom нужна `published`: одна лишь `updated` не выдаётся за дату публикации.

401/403/429 от RSSHub и распознанное ограничение Telegram в его ответе останавливают
сбор, без автоматического повтора. Retry-After сохраняется; без него действует
минимальная защитная пауза 60 секунд. Недоступность сервера и HTTP 502/503/504
также останавливают сбор, чтобы не расходовать запросы на все каналы подряд.
HTTP 404/обычный 500 отдельной ленты отмечаются как unavailable без повторов.

После устранения причины, восстановления доступа и окончания паузы продолжение
**того же экземпляра и того же состояния** разрешается явно:

```powershell
python -B scripts/classify_catalog.py collect --run reports/catalog-growth-6000/posts-run-1 --rsshub-url http://127.0.0.1:1200 --resume-rsshub --requests 3000 --hours 8
```

История продолжения записывается, счётчики и использованные попытки сохраняются.
Если заодно истёк deadline, добавьте `--extend-hours 8`. Этот флаг не снимает
остановку прежнего прямого Telegram-сборщика и сам по себе не меняет сервер.
Для недоступного сервера есть отдельный явный `--change-rsshub-url`, описанный выше;
после ограничений доступа он запрещён.
Остановка из-за исчерпанного бюджета также не снимается.

## 5. Дальнейшая классификация и t-SNE

При переключении текущего run пути **остаются прежними**:

```powershell
python -B scripts/classify_catalog_v11v2.py classify --post-cache reports/catalog-growth-6000/posts-run-1/posts --output reports/classification-v11v2/catalog-rsshub-1 --seconds 28800
```

После просмотра → publish → export, затем:

```powershell
python -B scripts/build_atlas_layout.py compare --methods tsne --post-cache reports/catalog-growth-6000/posts-run-1/posts --output reports/atlas-layout/tsne-rsshub-1
```

Для нового `posts-rsshub-1` подставьте его `posts` в обе команды. Публикация
по-прежнему отдельная, только после просмотра, по шагам 7–8 основной инструкции.
RSSHub сам не запускает ML, не меняет карту и не пишет публикации в рабочую БД.

## Проверка реализации

Проверены RSS 2.0 и Atom, content:encoded, HTML/XHTML, идентичность канала,
даты, размер, XML-сущности, фильтрация и совместимость кеша, миграция/продолжение
без сброса лимитов, остановки 403/429 и ошибки сервера. Выполнен настоящий HTTP
round-trip против локального тестового сервера с RSS-фикстурой.
Это не живой RSSHub и не замер скорости Telegram. Docker CLI в среде не найден;
развёртывание Compose и реальный маршрут RSSHub на этой машине не проверялись.
