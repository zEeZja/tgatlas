# Безопасность и данные

Не публикуйте пароли БД, `.env`, Telegram-сессии, browser profiles, cookies,
access keys и сырые дампы в issues, pull requests или скриншотах.

Если секрет попал в Git, сначала отзовите/замените его. Обычный коммит удаления
не стирает прежнее содержимое из истории репозитория. Переписывание истории и
удаление чужих данных выполняются только после отдельного согласования.

При сообщении об уязвимости не прикладывайте действующие секреты или данные
пользователей. Для обычной ошибки создайте issue с версией, безопасным примером
и шагами воспроизведения. Если доступен раздел GitHub **Security → Report a
vulnerability**, используйте его для чувствительных сообщений.
