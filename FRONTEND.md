# TG Atlas — тематическая карта каналов

Фронтенд на HTML, CSS, JavaScript без обязательных npm-зависимостей и сборщика.

## Быстрый запуск

Из корня проекта:

```bash
python -m http.server 4173 --directory web
```

Откройте http://localhost:4173. Также можно открыть `web/index.html` напрямую.

Без рабочей выгрузки используется явно отмеченный демокаталог из 779 записей исходного `config/channels.json`. Значения подписчиков не придуманы: в демо их нет. Наличие записи в демо не подтверждает актуальность канала; классификация опирается на доступные названия и исходные рубрики.

## Новая карта

По умолчанию каналы группируются **по темам**, а не по географическим координатам. Цвет всегда обозначает тему. Все каналы, включая федеральные и каналы без региона, присутствуют на карте.

- Переключатель «Группировка» меняет тематические кластеры на региональные.
- Режим «По регионам» использует географические центры регионов в проекции Ламберта, чтобы сохранить ориентир России с запада на восток. Плотные соседние острова немного смещаются для устранения пересечений. Это картограмма с приблизительными положениями, а не карта административных границ. Федеральные и каналы без координат расположены отдельно внизу.
- Точки размещаются детерминированно в свободных облаках, с проверкой минимального расстояния между окружностями. Регулярной сетки и прямоугольных секций нет. При фильтрации их координаты не меняются.
- Внутри темы формируются географические острова; между островами и тематическими архипелагами сохраняется свободное пространство. При приближении появляются подписи соседств. Кнопка «Рельеф» переключает мягкую подсветку и сглаженные контуры островов.
- Нажатие на кластер в легенде приближает его. Кнопка общего вида показывает текущую отфильтрованную выборку.
- Регион и страна остаются независимыми фильтрами. Например, можно выбрать Москву и политику одновременно.
- Колесо и кнопки +/− меняют масштаб; перетаскивание работает мышью и касанием.
- На телефоне список и карта переключаются кнопкой внизу экрана.

Карта больше не запрашивает `/api/geo-map` и не требует `build-geo-map`. Прежняя географическая команда и API остаются доступными для других инструментов проекта.

## Категории и география

Первый уровень — содержательная категория: спорт, политика, новости, технологии и остальные рубрики. В интерфейсе больше не нужно сначала выбирать широкую группу вроде «Жизнь и интересы».

Второй уровень — географический охват **внутри выбранной категории**:

- конкретный регион (выбирается непосредственно в списке регионов, без отдельной кнопки «Один регион»);
- несколько регионов (только по явному списку `regions`);
- вся страна (федеральный канал с известной страной или явное правило);
- международный охват (только явные данные или правило владельца);
- география не уточнена.

Далее можно выбрать конкретный регион. Список регионов и счётчики охвата учитывают выбранную категорию и страну. Например: «Политика → Один регион → Москва». Канал с несколькими регионами находится по каждому из них. При смене категории географический фильтр сбрасывается.

Отсутствие региона **не означает** международный охват. Кандидаты геоклассификатора и неподтверждённый регион не считаются доказательством охвата. Само упоминание города не меняет содержательную категорию. Слово «новости» также не вытесняет специализированную категорию: «Новости науки» относятся к науке.

На карте категория образует архипелаг, а география — острова внутри него. В режиме «По регионам» порядок меняется: регион → тематические соседства. Координаты не меняются при фильтрации. Посев случайности привязан к идентификаторам, поэтому повторная загрузка и другой порядок входных данных не перемешивают карту. Добавление новых данных может изменить общую компоновку.

Приоритет темы: локальная корректировка → правило владельца → специализированная рубрика каталога → признаки в названии, username и описании → исходная общая рубрика или «Не определено». При недостатке метаданных алгоритм помечает тему для проверки. Веса признаков не являются вероятностями.

Общие правила охвата задаются независимо от тем в `config/geography_overrides.json`. Пример структуры (замените username на свой):

```json
{
  "your_global_channel": {"scope": "global"},
  "your_regional_channel": {"scope": "multi_region", "regions": ["Москва", "Республика Татарстан"], "country": "RU"},
  "your_country_channel": {"scope": "country", "country": "RU"}
}
```

После изменения правил: `python scripts/sync_topics.py`, затем `python main.py export`. Для HTTP перезапустите API. Правила применяются и к старым выгрузкам в браузере.

Экспорт/API добавляют `primary_category`, `geography_scope`, `geography_regions`, `geography_country`, `geography_review_required`. Поля прежней схемы сохранены для совместимости; SQL-рубрики не перезаписываются. Множественная география и международный охват задаются явными метаданными или конфигурацией, а не угадываются по отсутствию региона.

### Исправление темы

В карточке откройте «Исправить тему», выберите рубрику и нажмите «Сохранить в этом браузере». Канал переместится в нужный кластер. Это локальная настройка, которая не изменяет PostgreSQL и не передаётся другим посетителям. Выбор «Автоопределение / данные каталога» удаляет локальную настройку.

Для общего исправления у всех посетителей используйте `config/topic_overrides.json`:

```json
{
  "channel_username": "politics",
  "another_channel": "science"
}
```

Ключ — username в нижнем регистре, без @; значение — ID темы из `config/topics.json`. После изменения правил выполните:

```bash
python scripts/sync_topics.py
python main.py export
```

Перезапустите HTTP API, если он уже работал. Файл `web/taxonomy.js` генерируется из конфигурации и хранится в Git для запуска через `file://`. Не редактируйте его отдельно. `web/topics.js` и `src/topic_keywords.py` реализуют одинаковые правила, что проверяется тестом на общих примерах.

Экспорт и `/api/channels` возвращают уточнённую `subcategory`, отдельную `topic_category`, исходную `original_subcategory`, источник, признаки и отметку проверки. Исходные категории в базе не перезаписываются. Старые выгрузки тоже уточняются в браузере.

## Рабочие данные

При обновлении существующей установки сохраните свой `.env` и папку `web/data`. Не заменяйте рабочие выгрузки заглушками из репозитория.

```bash
python main.py export
```

Рабочий `data/channels.js` имеет приоритет над демо. Для HTTP API задайте `CONFIG.mode = 'http'` и `httpBase` в `web/api.js`; демонстрационные данные в HTTP-режиме не используются. В репозитории нет `.env` и Telegram-сессий.

## Проверка

```bash
pip install -r requirements.txt
python -m unittest discover -s tests
npm ci
npm run test:layout
npx playwright install chromium
npm run test:frontend
```

На Linux можно использовать уже установленный Chromium: `CHROMIUM_PATH=/usr/bin/chromium npm run test:frontend`.

Тесты покрывают тематики и ложные совпадения, соответствие Python и браузера, экспорт, 2200 непересекающихся точек в двух режимах, стабильность раскладки, поиск, разделы/темы/регионы, сортировку, пагинацию, пустую выдачу, выбор точки, локальную корректировку и её сброс, мобильный режим и HTTP без географической выгрузки. Проверяются экраны 1440×1000, 1280×720, 768×1024, 390×844 и 360×640.

Проверка открытия через `file://` запускается отдельно: `ATLAS_TEST_FILE=1 npm run test:frontend`. Управляемый Chromium этой среды блокирует такие переходы политикой администратора (`ERR_BLOCKED_BY_ADMINISTRATOR`); обязательные браузерные проверки выполняются через локальный HTTP-сервер.

Живая PostgreSQL в этой сессии не запускалась. HTTP-поток проверен на тестовом ответе API; для полноценного каталога используйте реальные метаданные вашей базы.

## Визуальный референс и границы метода

Изучена [статья о TGPages](https://habr.com/ru/articles/992910/) и иллюстрации карты. У референса сходство строится по эмбеддингам описаний и публикаций с последующей кластеризацией и проекцией. В этой версии реализован собственный алгоритм органической упаковки и рельефа по категориям и географии, без копирования чужих координат, кода или данных. Расстояние здесь не является мерой смыслового сходства публикаций. Для настоящей семантической карты потребуется отдельный проверяемый этап анализа содержимого.

Живой TGPages в управляемом Chromium не открылся из-за ERR_CERT_AUTHORITY_INVALID; статья и её иллюстрации прочитаны через HTTPS с действующей проверкой сертификатов.

## Обновление регионов и быстрый опрос новостей

Однозначное название города или региона может восстановить географию из старой выгрузки, в том числе при устаревшем флаге проверки. Используются общие алиасы Python/браузера, включая формы «Новости Перми», «Новости Твери». Два разных региона в названии остаются неоднозначными; федеральный whitelist и ручные правила имеют приоритет. Тема от географии не меняется.

После обновления ветки выполните:

```bash
python scripts/sync_topics.py
python main.py export
python -m http.server 4173 --directory web
```

Для регионального режима выберите «По регионам». Фильтра «Один регион» больше нет — достаточно выбрать конкретный регион.

### Сбор публикаций

```bash
# Обычный повторный опрос: несколько каналов загружаются одновременно.
python main.py scrape --workers 4 --pages 3

# Один канал:
python main.py scrape --channel channel_username --workers 1 --pages 3

# Более глубокое чтение истории, включая уже известные посты, в заданном лимите:
python main.py scrape --full-history --pages 20
```

По умолчанию опрос инкрементальный: чтение прекращается, как только достигнут уже сохранённый ID. Поэтому неизменившийся канал обычно требует одну страницу вместо пяти. Начальная загрузка нового канала ограничена `--pages`/`MAX_PAGES` и не обещает полную историю.

Если при повторном опросе новых постов больше бюджета страниц, в `scrape_checkpoints` сохраняется курсор недочитанного участка. Следующий запуск сначала проверяет свежую страницу, затем продолжает этот участок. Посты и курсор сохраняются одной транзакцией; при ошибке записи откатываются вместе. Для продвижения по старому недочитанному участку нужно оставить больше одной страницы бюджета; при постоянном большом потоке увеличьте `--pages`. `--full-history` не отменяет лимит страниц и сохраняет существующий инкрементальный курсор.

Таблица курсоров создаётся при первом `scrape` автоматически; учётной записи нужны соответствующие права. Её также можно подготовить командой `python main.py init-db` от владельца схемы. Миграции существующих постов и удаление данных не требуются.

Настройки `.env`:

```dotenv
SCRAPE_WORKERS=4
SCRAPE_REQUEST_INTERVAL=1.0
MAX_PAGES=5
```

Одновременно работают 1–8 загрузчиков с отдельными HTTP-сессиями, но все запросы проходят через общий ограничитель частоты. Запись в PostgreSQL последовательная, посты вставляются пакетами с прежней дедупликацией. `429` устанавливает общую паузу по Retry-After, включая HTTP-date; ожидание Telegram не сокращается до прежнего потолка 60 секунд. Старые DELAY_MIN/DELAY_MAX больше не задают дополнительные паузы в команде scrape; они могут использоваться другими командами проекта.

Это ускоряет повторный сбор благодаря меньшему числу запросов и перекрытию сетевых ожиданий. Реальная скорость зависит от задержек Telegram, ограничений и базы. Производительность на живом Telegram/PostgreSQL в этой сессии не измерялась: проверены моделируемые запросы, ограничение числа загрузчиков, остановка по watermark, продолжение разрыва, общая пауза и пакетная запись. Генерация сводок в это изменение не входит; посты остаются в таблице posts для дальнейшей обработки.
